Product Requirements Document
StudyMate AI

Version: 1.0
Status: Ready for Development
Product Type: AI-powered educational web application
Primary Architecture: RAG + LLM
Target Users: Students from Classes 9–12
Primary Goal: Enable students to learn from their own study material through grounded AI Q&A and chapter-specific quizzes.

1. Product Overview
1.1 Product Name

StudyMate AI

Tagline

Learn from your material. Ask anything. Test yourself.

1.2 Product Vision

StudyMate AI is a class-aware, RAG-based AI learning platform that allows students to upload educational PDFs and interact with their study material through an AI tutor.

Unlike a generic AI chatbot, StudyMate AI should:

understand the student's class and subject,
process uploaded educational material,
identify chapters,
allow students to select specific chapters,
answer questions using only the selected study material,
provide source/page references,
generate quizzes exclusively from selected chapters,
evaluate quiz performance.

The product should feel like a digital study desk / intelligent textbook, not like a generic AI chatbot.

2. Problem Statement

Students often use general-purpose AI assistants to study, but those systems can:

provide information outside the student's syllabus,
use terminology inappropriate for the student's class level,
produce answers unrelated to their textbook,
make it difficult to identify where an answer came from,
generate quizzes from an entire subject instead of the chapter being studied.

StudyMate AI addresses this by grounding the AI in the student's uploaded educational material.

4. Core Product Principle

The most important principle of StudyMate AI is:

The selected study scope controls what the AI can use.

For example:

Class: 10
Subject: Artificial Intelligence
Material: AI_Textbook.pdf

Selected chapters:
✓ Chapter 2
✓ Chapter 3
✗ Chapter 4

If the student asks a question, retrieval must prioritize/filter content belonging to Chapters 2 and 3.

If the student generates a quiz, questions must be generated exclusively from Chapters 2 and 3.

The application must never silently expand the scope to the entire textbook.

After upload, the backend should:

13. Grounded Answer Requirements

The AI must:

prioritize retrieved material,
avoid inventing textbook-specific information,
answer at the student's selected class level,
clearly indicate when information isn't available in the selected material,
avoid pretending that external knowledge came from the textbook.

If the answer cannot be supported by the selected material:

"I couldn't find enough information about this in the selected chapters."

The system should not hallucinate an answer simply to satisfy the query.

32. RAG Metadata

Every vector must retain:

{
  "document_id": "doc_001",
  "document_name": "AI_Textbook.pdf",
  "class": "10",
  "subject": "Artificial Intelligence",
  "chapter_number": 3,
  "chapter_title": "Machine Intelligence",
  "page": 42
}

Retrieval must support metadata filtering.

Example conceptual filter:

document_id = doc_001
AND chapter_number IN [2, 3]
33. RAG Requirements

The system must:

Extract page-level text.
Detect chapters.
Preserve chapter boundaries.
Chunk content.
Generate embeddings.
Store vectors with metadata.
Filter by selected chapters.
Perform similarity search.
Send retrieved context to Gemini.
Return answer + sources.
34. Hallucination Control

The system prompt should establish:

Answer using the provided retrieved context.

If sufficient information isn't present:

"I couldn't find enough information about this in the selected material."

The AI should not fabricate:

page numbers,
textbook statements,
chapter content,
citations.
35. Quiz Reliability

Quiz generation should return structured JSON.

Example:

{
  "title": "Machine Intelligence",
  "questions": [
    {
      "question": "...",
      "type": "multiple_choice",
      "options": [
        "...",
        "...",
        "...",
        "..."
      ],
      "correct_answer": 0,
      "explanation": "...",
      "source": {
        "chapter": 3,
        "page": 42
      }
    }
  ]
}

The backend should validate the generated structure before sending it to the frontend.

V1 should:

only accept PDFs,

validate LLM JSON before returning it.

41. Antigravity Implementation Instruction

Treat this PRD as the source of truth.

Before implementing:

Inspect the repository.
Create a clean frontend/backend structure.
Do not introduce unnecessary dependencies.
Do not invent additional product features.
Build reusable components.
Keep business logic out of React components.
Keep Gemini credentials exclusively on the backend.
Keep RAG logic modular and independently testable.
Implement the RAG backend before building complex frontend interactions.
Use realistic loading, empty, error, and processing states.
Follow the specified visual system exactly.
Do not use generic AI SaaS UI patterns.
Do not use gradients, glassmorphism, neon colors, excessive shadows, or excessive rounded cards.
Prioritize typography, spacing, hierarchy, and usability.
Preserve chapter metadata throughout the entire RAG pipeline.
Use the same chapter-scoped retrieval system for both Q&A and quiz generation.
Validate structured LLM responses before displaying them.
Never expose API keys in client-side code.
Keep V1 intentionally small and presentation-ready.
Most important product rule

StudyMate AI is not a generic chatbot. It is a study-material-grounded AI tutor.

The student's selected class + subject + document + chapter scope should remain central to the application's behavior.
